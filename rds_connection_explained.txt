║   为什么我的 Mac 终端访问 AWS RDS 数据库会被拒绝？                          ║
║   （结合 VPC_rules.ts 的代码 + Nitro 芯片的行为逐步拆解）                   ║
╚══════════════════════════════════════════════════════════════════════════╝


场景
────
你在家里的 Mac 上敲：
    $ psql -h mydb.abcd1234.ap-southeast-2.rds.amazonaws.com -U admin -d prod
结果：
    psql: error: connection timed out         ← 卡住，最后超时
或：
    psql: error: Connection refused            ← 直接被拒


先认清「两个世界」
──────────────────
你的 Mac 在【公网世界】，用的是家里路由器给的公网 IP，比如 123.45.67.89
RDS 数据库在【AWS 的 VPC 世界】里，它的网卡(ENI)拿到的是【私有 IP】，比如 10.0.1.20

  私有 IP（10.x / 172.16-31.x / 192.168.x）互联网上是不可路由的。
  也就是说：你的包根本「找不到路」到 10.0.1.20。

 全景图：一个数据包从 Mac 出发，尝试到达 RDS
═══════════════════════════════════════════════════════════════════════════

  ┌───────────────┐
  │   你的 Mac     │  psql 发出一个 TCP 包
  │ 123.45.67.89  │  目标端口 5432 (Postgres)
  └───────┬───────┘
          │  packet = { src: 123.45.67.89, dst: ???, dstPort: 5432 }
          ▼
  ┌───────────────────────────────────────────────────────────┐
  │                      公共互联网                              │
  └───────┬───────────────────────────────────────────────────┘
          │
          │  ✦ 关卡 0：DNS 解析出来的地址是「公网」还是「私网」？
          │
    ┌─────┴──────────────────────────────────────────────┐
    │                                                     │
    ▼ 情况A：RDS 是 Publicly Accessible = NO               ▼ 情况B：= YES
      域名解析成 10.0.1.20（私有IP）                          域名解析成公网IP 54.x.x.x
      → 你的包在互联网上根本无法路由                           → 包能到达 AWS 边界，继续往下走
      → 连 AWS 的门都到不了，直接超时 ❌                        │

                                                             ▼
                              ┌──────────────────────────────────────────┐
                              │  AWS 边界：InternetGateway (IGW)           │
                              │                                            │
                              │  对应代码 VPC_rules.ts:                     │
                              │    class InternetGateway {                 │
                              │      translateInbound(packet) {  // 公→私  │
                              │        packet.destinationIP =              │
                              │          natTable.get(dst)                 │
                              │      }                                     │
                              │    }                                       │
                              │                                            │
                              │  ✦ 关卡 1：这个 VPC 挂了 IGW 吗？           │
                              │     if (vpc.internetGateway == null)       │
                              │        → 没门，进不来 ❌                    │
                              └──────────────────┬─────────────────────────┘
                                                 │  包进入 VPC，目标 10.0.1.20
                                                 ▼
        ┌────────────────────────────────────────────────────────────────┐
        │            Nitro 芯片 (跑在承载 RDS 的物理宿主机上)               │
        │            = 代码里的 NitroForwardingEngine.forward()            │
        │                                                                  │
        │  这块芯片是「真正执行所有网络规则的地方」。它逐条检查：           │
        │                                                                  │
        │  ✦ 关卡 2：路由表 RouteTable —— 目标 10.0.1.20 怎么走？           │
        │     longestPrefixMatch(routes, "10.0.1.20")                      │
        │     命中 { destination: "10.0.0.0/16", target: "local" }         │
        │     → target = "local"，说明目标在 VPC 内，交给本地投递           │
        │                                                                  │
        │  ✦ 关卡 3：Security Group 入站规则（最常见的第二个拦截点！）      │
        │     代码：                                                        │
        │       if (!this.checkInboundSG(targetENI, packet)) {             │
        │           drop(packet);   // ← 直接丢弃，你就超时了              │
        │       }                                                          │
        │                                                                  │
        │     SecurityGroup 默认：                                         │
        │       constructor() {                                            │
        │         // 入站规则数组是空的 → 默认「全部拒绝」                  │
        │         inboundRules = []                                        │
        │       }                                                          │
        │                                                                  │
        │     除非你手动加过：                                             │
        │       sg.allowInbound("tcp", 5432, "123.45.67.89/32")            │

        │     如果没加这条 → checkInboundSG 返回 false → drop() ❌          │
        └──────────────────────────────┬───────────────────────────────────┘
                                        │ 全部通过才会：
                                        ▼
                              ┌───────────────────────┐
                              │  RDS 的网卡 ENI        │
                              │  privateIP: 10.0.1.20  │   deliver(packet, eni)
                              │  → Postgres 收到连接    │   连接成功 ✅

 「被拒绝」的三大真凶（按发生概率排序）
═══════════════════════════════════════════════════════════════════════════

┌───┬────────────────────────┬─────────────────────────────┬──────────────────┐
│ # │ 原因                    │ 对应代码里的哪一步            │ 现象              │
├───┼────────────────────────┼─────────────────────────────┼──────────────────┤
│ 1 │ RDS 不是 Public，       │ 域名解析出私有IP 10.0.1.20   │ connection       │
│   │ 你在公网根本路由不到    │ 包在互联网上无法路由，        │ timed out        │
│   │ （最常见）              │ 连 IGW 都到不了               │ (卡很久)         │
├───┼────────────────────────┼─────────────────────────────┼──────────────────┤
│ 2 │ Security Group 没放行   │ Nitro 执行 checkInboundSG()  │ connection       │
│   │ 你的 IP + 5432 端口     │ → 返回 false → drop(packet)  │ timed out        │
│   │ （第二常见）            │ 默认 inboundRules = [] 全拒   │ (包被静默丢弃)   │
├───┼────────────────────────┼─────────────────────────────┼──────────────────┤
│ 3 │ 子网没有 IGW 路由 /     │ RouteTable.routes 里没有     │ timed out /      │
│   │ RDS 在私有子网          │ 0.0.0.0/0 → igw-xxx          │ 无法建立连接     │
└───┴────────────────────────┴─────────────────────────────┴──────────────────┘


═══════════════════════════════════════════════════════════════════════════
 Nitro 芯片到底在干嘛？（把它和代码对齐）
═══════════════════════════════════════════════════════════════════════════

关键认知：
    VPC / Subnet / RouteTable / SecurityGroup 这些东西，你在 AWS 控制台里
    「配置」它们，但它们本身只是「规则数据」。
    真正「执行」这些规则、决定每一个数据包是放行还是丢弃的，
    是每台物理宿主机上的 Nitro 芯片。

    ┌─────────────────────────────────────────────────────────┐
    │  你在控制台点点点  →  只是往这些对象里写数据             │
    │     RouteTable.routes = [...]                            │
    │     SecurityGroup.inboundRules = [...]                   │
    │                                                          │
    │  数据库真正收到包的瞬间  →  Nitro 芯片读这些数据来裁决   │
    │     NitroForwardingEngine.forward(packet, eni) {         │
    │        1. longestPrefixMatch()  查路由                   │
    │        2. checkInboundSG()      查安全组                 │
    │        3. drop() 或 deliver()   丢弃 or 投递             │
    │     }                                                    │
    └─────────────────────────────────────────────────────────┘

    所以「被拒绝」这个动作，物理上就发生在
    ↓↓↓ 代码的这一行 ↓↓↓
        if (!this.checkInboundSG(targetENI, packet)) {
            drop(packet);      // ← Nitro 在硬件层面把你的包扔掉了
        }
    它不给你任何回复，于是你的 Mac 傻等 → 最终 "connection timed out"。

    （对比：如果是「Connection refused」，通常是包到了机器、
      但数据库进程没监听那个端口，或防火墙主动 REJECT；
      而 Security Group 的丢弃是「静默 DROP」，表现为超时。）

 怎么修？（逐个对应上面的真凶）
═══════════════════════════════════════════════════════════════════════════

修真凶#2（最容易自查）——给 Security Group 放行你的 IP：
    在 RDS 的 Security Group 里加一条入站规则：
        类型: PostgreSQL   端口: 5432   来源: <你的公网IP>/32
    等价于代码：
        sg.allowInbound("tcp", 5432, "123.45.67.89/32")
    查自己公网IP：浏览器搜 "what is my ip"，或终端 `curl ifconfig.me`

修真凶#1/#3（架构层面）——两种主流做法：
    做法A（图省事，仅测试用）：
        把 RDS 设为 Publicly Accessible = Yes
        + 放在 public 子网（路由表有 0.0.0.0/0 → igw）
        + Security Group 放行你的 IP
    做法B（生产推荐，安全）：
        RDS 保持私有（Publicly Accessible = No）
        你的 Mac 先连到 VPC 内部，再从内部连 RDS：
          - 用堡垒机 (Bastion Host) SSH 隧道，或
          - 用 AWS Systems Manager Session Manager，或
          - 用 VPN / AWS Client VPN
        这样你的包「从 VPC 内部」发起，走 local 路由，
        自然就不需要走公网了。

 一句话总结
═══════════════════════════════════════════════════════════════════════════
    你的包被拒，99% 是这两件事之一：
      ① 你根本没路由到它（RDS 是私有 IP，公网找不到）—— 关卡 0/1
      ② 路由到了，但 Nitro 芯片执行 Security Group 时把你 drop 了 —— 关卡 3
    而 InternetGateway 是唯一的「门」，Nitro 芯片是唯一的「门卫」。
